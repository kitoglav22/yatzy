# Бот Яцзы

Один воркер Cloudflare Workers без зависимостей: `worker.js` целиком вставляется в редактор кода воркера.

- **Запросы приложения** приходят не напрямую, а через базу Firebase: приложение кладёт короткую запись в `req/`, воркер забирает её при следующем запуске (раз в минуту) и удаляет. Так бот работает и там, где Cloudflare недоступен. Виды запросов: `hello` (кто из комнаты играет из этого Telegram), `nudge` (кнопка «Поторопить»), `moved` (в комнате записана клетка или началась партия). `hello` и `nudge` подписаны Telegram (`initData`), воркер проверяет подпись токеном бота.
- **Таймер** раз в минуту (cron `* * * * *`): запросы, «твой ход» тем, кто вышел из приложения, напоминания раз в сутки (не больше трёх на ход), рейтинг после партии. В тихую минуту воркер читает только `req` и `srv`, комнаты целиком только когда в них сходили или пора писать.
- **Уборка**: в тихую минуту, по 10 комнат за раз, не чаще одного прохода в сутки, бот удаляет комнаты, которые никто не трогал 60 дней (время последнего изменения приложение пишет в `t`).
- **Надёжность**: данные комнаты проверяются, сломанная комната пропускается и забывается, остальные работают. Сообщения уходят только после записи в базу, поэтому неудачная запись не даёт повторов.
- **Оформление бота**: описание в пустом чате, строка «о боте», команды `/start`, `/arcade`, `/yatzy` и кнопка меню «Играть» (открывает сайт блокнота) задаются в начале `worker.js` и записываются в Telegram ссылкой настройки (ниже), BotFather для этого не нужен. Кнопка «Играть в аркаду» ведёт на `…/play?startapp=arcade`: блокнот в Telegram сразу открывает аркаду.
- **Вебхук Telegram**: `/start`, `/arcade`, `/yatzy`, `/news`, кнопка «Не присылать новости» и инлайн-режим `@k22_yatzy_bot` (приглашение из любого чата). Заголовок `X-Telegram-Bot-Api-Secret-Token` должен совпадать с `HOOK_SECRET`.
- **Новости аркады**: сборка аркады (`tools/build.mjs` в yatzy-arcade) кладёт во второй комментарий `arcade.html` строки «Что нового» последних выпусков: `<!-- arcade-news {"arcade":37,"version":"72.37","news":{…}} -->`. Воркер раз в пять минут читает начало опубликованной страницы (первые 16 КБ; `NEWS_HOUR` = час по Москве вместо этого собирает выпуски дня в одно вечернее сообщение) и пишет всем, кого знает, строки выпусков, о которых ещё не говорил: новые первыми, не больше пяти, по 20 сообщений в минуту, только в тихую минуту. Самый первый взгляд лишь запоминает номер выпуска. Под сообщением кнопки «Играть в аркаду» (`startapp=arcade_news`, аркада видит `?from=news`) и «Не присылать новости» (`srv/quiet/<id>`); `/news` включает их снова. Выпуск без строк (только полировка) — без сообщения. Состояние рассылки — `srv/news`.

Данные бота лежат в той же базе в `srv/`; правила базы (`database.rules.json`) его не открывают, воркер входит сервисным аккаунтом. Приложению видно только `pub/`: `pub/bot` (бот работает, у приложения появляются его кнопки), `pub/tg/<комната>` (кому бот может написать) и `pub/rating` (строки помечены хешем id Telegram, не самим id).

Секреты: `BOT_TOKEN`, `FB_SA` (JSON ключа сервисного аккаунта Firebase), `HOOK_SECRET`. Необязательные переменные: `FB_URL`, `APP_LINK`, `SITE` (адрес кнопки меню).

После развёртывания откройте адрес воркера с `?setup=<HOOK_SECRET>`: воркер подключит себя как вебхук бота, запишет оформление бота (строка `look`), проверит Telegram и Firebase, разберёт очередь и покажет, что не так (строка `news` — какой выпуск аркады бот уже знает): сколько запросов ждёт и как давно (старые значат, что не работает таймер), сколько подписей не сошлось и какие поля были в последней неверной.

Тесты: `tests/bot.test.js` (воркер с поддельной базой и Telegram) и `tests/tgbot.test.js` (приложение вместе с ботом).
